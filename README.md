# Расчёт фокусировки лазерного излучения на детали

Мобильное приложение (Kivy → Android APK), повторяющее расчёт из книги
«Расчет оптики», лист «Сравнение оптических схем». Сравнивает до пяти
оптических схем одновременно и строит схему фокусировки: каустику пучка,
деталь с разделкой кромок, присадочную проволоку и режущее сопло.

## Что считается

Для каждой схемы задаются длина волны, диаметр волокна, BPP, фокусные
расстояния коллиматора и фокусатора, положение фокуса, угол наклона луча,
скорость обработки и мощность.

| Величина | Формула |
|---|---|
| Увеличение оптики | `Γ = f_фок / f_кол` |
| Диаметр пятна в фокусе, мм | `d₀ = 10⁻³ · d_волокна · Γ` |
| Длина Рэлея, мм | `z_R = 10³ · (d₀/2)² / BPP` |
| Длина перетяжки, мм | `L = 2·z_R` |
| Диаметр пятна на расстоянии Δz | `d(Δz) = d₀·√(1 + (Δz/z_R)²)` |
| Пятно на поверхности | `d(Δf)`, где Δf — положение фокуса |
| Пятно в корне шва | `d(Δf + t)`, t — толщина детали |
| Расфокусировка под заданное пятно | `Δz = z_R·√((d_треб/d₀)² − 1)` |
| Параметр качества пучка | `M² = BPP·π / λ` |
| Диаметр пучка на линзе, мм | `D = 4·f_кол·BPP / d_волокна` |
| Сдвиг фокуса на 1 мм коллиматора | `(f_фок / f_кол)²` |
| Плотность мощности, Вт/см² | `P / (π·d²/4)`, d в см |
| Погонная энергия, Дж/мм | `P[Вт] / v[мм/с]` |

Знак положения фокуса: «+» — перетяжка над поверхностью детали, «−» — под ней.
Положительный угол скоса кромки — разделка расширяется кверху (V-образная),
отрицательный — книзу.

**Сверка с исходной книгой.** `tests/test_optics.py` проверяет расчёт по
контрольным значениям схем 1 и 4 из Excel — совпадение полное. Единственное
намеренное расхождение: в книге в формулах плотности мощности стоит `3,14`,
здесь используется `math.pi`, отсюда разница около 0,05 %.

## Запуск на компьютере

```bash
pip install kivy==2.3.1
python main.py
```

Тесты (Kivy не требуется):

```bash
python tests/test_optics.py
```

## Сборка APK через GitHub

1. Создайте репозиторий и загрузите папку целиком (вместе с `.github/`).
2. `git push` в ветку `main` — workflow **Сборка APK** запустится сам.
3. Готовый файл — во вкладке **Actions** → нужный запуск → раздел
   **Artifacts** → `laseroptics-debug-apk`.
4. Тег вида `v1.0.0` дополнительно приложит APK к релизу:

```bash
git tag v1.0.0 && git push origin v1.0.0
```

Первая сборка занимает 25–40 минут (скачиваются Android SDK и NDK),
последующие — 5–10 минут за счёт кэша.

### Локальная сборка

```bash
pip install buildozer cython==0.29.36
buildozer -v android debug        # bin/*.apk
buildozer -v android release      # bin/*.aab для магазина
```

## Структура

```

app/ui.py                интерфейс: вкладки «Параметры», «Результаты», «Схема»

.github/workflows/       автосборка APK
```

## Работа с приложением

**Параметры.** Схема выбирается в списке вверху; заполняются только те схемы,
которые нужно сравнить (незаполненные — с нулевым коллиматором или
фокусатором — в расчёт не идут). Геометрия детали, проволоки и сопла общая для
всех схем. Кнопка «Сохранить» пишет состояние в JSON, оно восстанавливается
при следующем запуске.

**Результаты.** Таблица по всем заполненным схемам, цвет заголовка совпадает с
цветом пучка на схеме. Ниже — предупреждения (недостижимое пятно, высокая
плотность мощности на защитном стекле, большой зазор без присадки). Кнопка
выгружает CSV с разделителем `;` и запятой в дробной части — открывается в
Excel без настройки импорта.

**Схема.** Перетаскивание — пальцем, масштаб — кнопками «−» / «+», «Вписать»
возвращает исходный вид. Кружком отмечено положение перетяжки, пунктиром —
поверхность детали. Пучок обрезается по выходной апертуре фокусатора.

## Что не перенесено

«Лист1» исходной книги (кольцевая сварка: углы нарастания и спада мощности,
задержка и упреждение подачи проволоки) содержит сплошные `#REF!` —
формулы ссылаются на удалённые ячейки, восстановить исходный замысел по ним
нельзя. Если этот расчёт нужен, опишите постановку — добавлю отдельной вкладкой.
